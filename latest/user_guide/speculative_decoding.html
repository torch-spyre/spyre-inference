    XPress speculative decoding¶

    XPress runs a DFlash backbone once, refines a block of draft tokens, and lets the target model verify the proposals. The experimental Spyre integration loads published XPress checkpoints directly for Qwen3-8B and Gemma 4 26B A4B; checkpoint conversion is not required.

    Supported configuration: compiled FP16, unquantized weights, TP=1, PP=1, either model runner (SPYRE_MODEL_RUNNER=v1 or v2), up to four active requests, and prefix caching disabled. The checkpoint fixes the block at one anchor plus 15 proposals. The four-request cap reflects the batches validated on Spyre so far. Larger batches require additional device validation before raising this limit.

    Run Qwen3-8B¶

    export SPYRE_MODEL_RUNNER=v2  # or v1
export SPYRE_ATTN_QUERY_BUCKETS=1,16,64
uv run --no-sync vllm serve Qwen/Qwen3-8B \
  --revision b968826d9c46dd6066d109eabc6255188de91218 \
  --tokenizer-revision b968826d9c46dd6066d109eabc6255188de91218 \
  --dtype float16 --tensor-parallel-size 1 \
  --max-num-seqs 1 --max-model-len 512 --max-num-batched-tokens 64 \
  --no-enable-prefix-caching \
  --compilation-config '{"compile_sizes": [1, 16, 64]}' \
  --speculative-config '{"method": "dflash", "model": "UIUC-SSAIL/Qwen3-8B-XPress-b16", "revision": "f098ab5bbe4fce37c4a1093266bcd8ad15df5cb5", "num_speculative_tokens": 15, "xpress_topc": 128}'

    Requests can use greedy (temperature=0) or stochastic target sampling, including temperature, top-k and top-p. The drafter remains greedy; vLLM treats its proposals as point-mass distributions during CPU rejection sampling. The same speculative configuration works with vllm.LLM. The end-to-end test (tests/e2e/test_xpress_v2.py) and CI's public-model cache list pin the same model and checkpoint revisions as this example; update all three together. A full verification round needs at least 31 budgeted tokens because vLLM reserves additional drafting slots; the adapter rejects a smaller budget.

    For four concurrent requests, set --max-num-seqs 4, --max-num-batched-tokens 128, and --compilation-config '{"compile_sizes": [1, 16, 32, 64, 128]}'. Set SPYRE_ATTN_QUERY_BUCKETS=1,16,64,128 for this token budget. Set SPYRE_MAX_NUM_PARTIAL_PREFILLS=4 to allow four partial prefills. The draft body uses batches of 1, 2, or 4; three active requests pad to four. Each request retains its own accepted context, page table, and output limit.

    The batch-four PR test uses these settings. Trunk CI additionally covers default attention buckets, compilation sizes and the default single partial prefill.

    Maximum requests Minimum token budget
    1 31
    2 62
    3 93
    4 124

    Run Gemma 4 26B A4B¶

    The Gemma-trained checkpoint uses the same Qwen3 XPress draft architecture, with four sliding causal layers and one full non-causal layer. Spyre preserves these settings and captures the six target layers specified by the checkpoint. Use the text-backbone override to load the target's decoder:

    export SPYRE_MODEL_RUNNER=v2  # or v1
export SPYRE_ATTN_QUERY_BUCKETS=1,16,64
uv run --no-sync vllm serve google/gemma-4-26B-A4B-it \
  --revision 4d7ae4984b7db7de8f8457170b3f1a419ee76d52 \
  --tokenizer-revision 4d7ae4984b7db7de8f8457170b3f1a419ee76d52 \
  --hf-overrides '{"architectures": ["Gemma4ForCausalLM"]}' \
  --dtype float16 --tensor-parallel-size 1 \
  --max-num-seqs 1 --max-model-len 256 --max-num-batched-tokens 64 \
  --no-enable-prefix-caching \
  --compilation-config '{"compile_sizes": [1, 16, 64]}' \
  --speculative-config '{"method": "dflash", "model": "UIUC-SSAIL/gemma4-26b-a4b-XPress-b16", "revision": "e69e3580df7a7cd76b77e82ef739803fd88ee445", "num_speculative_tokens": 15, "xpress_topc": 128}'

    The explicit xpress_topc=128 overrides this checkpoint's 512-candidate default. The draft shares the target's raw embedding and output-head weights, matching upstream; Gemma's embedding scaling and logit softcap remain in the target.

    Refinement and compatibility¶

    The refiner follows merged vLLM XPress: a fixed anchor, causal Jacobi updates, a block-wide hidden summary, and candidate sets fixed across passes. Target input embeddings and output-head weights are shared separately. Accepted target states populate the draft KV cache; rejected and padded rows write only the reserved null page.

    xpress_topc overrides the checkpoint field. Spyre defaults to 128 when neither supplies a value. The effective shortlist is min(xpress_topc, vocab_size) and must contain 1 to 1024 candidates; unsupported configurations fail before model loading. Full-vocabulary refinement (xpress_topc=0) is unsupported. A smaller shortlist can change acceptance. The checkpoint selects the pass count, with six as the default.

    Replaying a seeded request with the same configuration is deterministic. Changing between ordinary decoding, DFlash and XPress changes RNG consumption; the same seed need not produce identical tokens across these modes.

    Spyre subclasses upstream's XPress model and drives refinement from its own propose_block, called by the V1 DFlash proposer and by the V2 runner's DFlash speculator. Initial vocabulary top-k runs on CPU. Refinement and per-pass selection stay on Spyre; each pass selects the next token embeddings directly from the shortlist. Only the final shortlist positions return to CPU to recover token IDs.

    Spyre computes refiner scores in FP16/DL16 and picks the first tied shortlist position. Widening these scores to FP32 on CPU preserves the same ties. Upstream Triton's FP32 arithmetic can produce different drafts. DL16 represents supported shortlist positions and the selection sentinel exactly.

    The refiner caches an input embedding per candidate for the current draft block. This avoids the device integer-layout conversions needed to feed token IDs back into an embedding lookup. Direct gathers with device-generated indices remain dependent on torch-spyre support.

    On the V2 runner, upstream's DFlash speculator does the draft bookkeeping, and its Triton kernels run through triton-cpu, so V2 speculative decoding is x86-only for now (#1238).

    Validation¶

    uv run --no-sync pytest tests/spec_decode -m 'not upstream'
uv run --no-sync pytest tests/e2e/test_xpress_feedback.py -m 'not upstream' -s
uv run --no-sync pytest tests/e2e/test_xpress_v2.py -m model_quality -s

    The end-to-end check runs on the V2 runner, which replaces V1. On V1, XPress is covered by the unit tests in tests/spec_decode until the V1 runner is removed.

    PR regression jobs prefetch both pinned models before running the quality gate. On Spyre, missing checkpoints fail the tests instead of skipping coverage.

    Validation covers recurrence, sampling, lifecycle, scripted rejection, full acceptance, DFlash and XPress. Stopping, cancellation and cache reuse checks include exact controlled-cache comparisons.

    A known numerical limitation remains: nearly tied FP16 target scores can select different greedy tokens between ordinary decoding and block verification. The counting prompt avoids the previously observed Spain/Germany tie; the underlying numerical difference is not fixed. Repeat device validation with C512 when qualifying that configuration.

    The batch engine also checks seeded replay across ordinary decoding, DFlash and XPress with temperature, top-k, top-p and combined filtering near the context limit. Replays compare exact tokens, logprobs and caches without building another engine for stochastic sampling.

    The 503-token case starts too close to the context limit to draft. A separate 495-token case verifies that a previously nonempty draft is cleared at the limit and that the next target step has no scheduled draft tokens. Validation timings are collected by the test worker; the serving loop has no timing counters.

    The batch-four test enables SPYRE_COMPILE_GUARD=error, including for partial prefill and shrinking batches. Warmup compiles the draft context KV stores at each target row bucket using the reserved null page.
